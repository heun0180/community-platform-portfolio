# 기능 및 개발 진행 기록

이 문서는 **완료·검증·설계**를 혼동하지 않도록 작성한 포트폴리오 기록입니다. 기준: 2026-11-19까지 확인된 구현 보고와 개발 대화. 로컬 Obsidian 폴더 전체 및 원격 Git 커밋을 대조한 최종 감사는 아닙니다.

## 인증

**요구사항:** 이메일/비밀번호 가입과 Discord 로그인 모두 지원. 이메일 인증 수단과 Discord 연동은 별개이며, 이메일로 가입한 사용자도 나중에 Discord 계정을 연결할 수 있어야 합니다.

**설계 포인트:** Discord의 변경 불가능한 사용자 ID를 저장하고 계정 중복 연결을 방지합니다. 기존 GuildUp 구현을 참고하지만 신규 프로젝트에서 실행·테스트된 범위만 완료로 판단합니다.

## 커뮤니티

- 기본 공개 정책은 **비공개**.
- 커뮤니티 생성 시 게임 **하나**를 선택합니다.
- 가입은 **관리자 승인** 정책을 적용합니다.
- 커뮤니티 권한은 **OWNER / ADMIN / MEMBER** 중심이며 게스트 역할은 현행 요구사항에서 제외되었습니다.
- 서로 다른 커뮤니티의 사용자·클랜 데이터는 분리되어야 합니다.

## Discord 연동과 회원 연결

**M4 개발 보고(2026-11-18):** 자동 테스트 98개와 프론트엔드 빌드 통과. 브라우저 화면 확인, 실제 Discord 동기화, 개발 DB 마이그레이션은 미실행으로 보고되었습니다.

회원 자동 연결의 기준은 다음과 같습니다.

1. 서비스 로그인 사용자의 Discord OAuth 사용자 ID를 확인합니다.
2. 현재 연결된 Discord 서버에서 지정 역할 보유가 마지막 성공 동기화에 확인된 활성 클랜원을 후보로 삼습니다.
3. 두 Discord ID가 **정확히 일치**하고 해당 커뮤니티 회원 기록이 없으면 MEMBER 연결을 생성합니다.
4. 기존 OWNER/ADMIN/MEMBER 역할과 탈퇴·추방 이력을 유지하며, 닉네임·이메일로 대신 매칭하지 않습니다.
5. 시스템 처리 사실을 감사 이력으로 기록합니다.

**검증 상태:** 코드·자동 테스트 통과 보고와 실제 Discord API/봇/DB 적용 성공은 구분합니다.

## 게임과 활동

게임은 커뮤니티 생성 시 정해지는 기능 경계입니다. 현재 대상은 PUBG이며 **Kakao / Steam shard**를 별도로 관리할 필요가 있습니다. 향후 게임이 늘어날 때 연동 데이터 모델과 화면 기능이 달라질 수 있도록 설계합니다.

**활동 규칙(기존 프로젝트 경험):** 최근 N일 동안 같은 스쿼드에 클랜원 M명(본인 포함) 이상이 있었는지를 집계하는 방식. 기본 운영 예시는 14일, 2명입니다. 이 규칙을 차기 프로젝트에 완전히 이관했는지는 별도 확인해야 합니다.

**닉네임 파싱(설계·검토):** 운영진이 Discord 표시명과 실제 게임 닉네임의 예시를 지정하여 구분자·위치 규칙을 추론합니다. 문자열 추출에 성공했다고 실제 PUBG 계정이 확인된 것은 아니며, 계정 검증은 별도 단계입니다.
