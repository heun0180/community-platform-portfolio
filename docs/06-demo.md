# 데모 버전 살펴보기

이번에 GitHub에 올린 버전에는 회원 관리뿐 아니라 PUBG 이벤트와 랭킹까지 연결하는 흐름이 들어갔습니다. 화면과 API 코드를 기준으로 정리한 내용입니다.

## 화면에서 볼 수 있는 흐름

### 1. 계정 만들기와 커뮤니티 선택

이메일이나 Discord로 로그인한 뒤 커뮤니티를 생성하거나 기존 커뮤니티에 가입합니다. 커뮤니티마다 게임과 플랫폼, 구성원 권한을 따로 관리합니다.

운영자는 가입 신청을 확인하고 멤버를 관리합니다. 일반 회원은 자신의 커뮤니티에서 허용된 메뉴만 이용합니다.

### 2. Discord와 게임 계정 연결

커뮤니티 운영자는 Discord 서버를 연결하고 클랜원과 역할을 동기화합니다. 표시명은 바꿀 수 있으므로 회원 연결에는 Discord 고유 ID를 사용합니다.

PUBG 기능에서는 Kakao와 Steam을 구별하고 게임 계정을 확인합니다. 닉네임 규칙을 적용할 때는 추출 결과를 먼저 확인할 수 있게 했습니다.

### 3. PUBG 활동 조회

운영자가 기간과 함께 플레이한 클랜원 수, 필요한 경기 수를 정하면 그 조건으로 활동을 조회합니다. 조회 결과에는 인정 여부뿐 아니라 근거가 되는 경기 기록도 포함됩니다.

외부 API를 조회하는 동안 웹 요청을 계속 붙잡지 않도록 수집 작업과 결과 조회를 나눴습니다.

### 4. 킬내기

대회를 만들 때 개인전·듀오·스쿼드 중 하나를 고르고, 킬 점수와 순위 보너스를 정합니다. 참가 신청과 팀 관리, 중간 집계, 종료 후 최종 정산을 위한 화면이 있습니다.

대회가 끝났다고 바로 모든 기록을 확정하지는 않습니다. 마감 직전에 시작한 경기가 늦게 끝날 수 있기 때문입니다. 종료 시각과 경기 시작 시각을 구분하고, 결과를 수집한 뒤 점수를 계산하도록 했습니다.

### 5. PUBG 빙고

운영자가 미션과 빙고판을 만들면 참가자는 경기 기록에 따라 칸을 채울 수 있습니다. 킬·피해량처럼 경기 상세에서 확인할 수 있는 수치와, 아이템 사용이나 특정 처치처럼 텔레메트리를 읽어야 하는 수치를 구분합니다.

미션 조건에 따라 봇 처치를 제외할 수 있고, 미션을 인정받은 경기도 확인할 수 있도록 화면을 구성했습니다.

### 6. 월간·누적 랭킹

랭킹은 커뮤니티마다 별도로 계산합니다. 이번 달과 지난달, 누적 점수를 조회할 수 있으며 동점자는 같은 순위를 갖습니다.

점수가 어떻게 쌓였는지 추적할 수 있도록 총점만 저장하지 않고 변경 이력도 함께 남깁니다. 같은 대회의 보상을 다시 처리하더라도 한 번만 적립되도록 중복 방지 키를 사용합니다.

## 데모를 만들면서 신경 쓴 부분

**경기 기록을 기능마다 다시 가져오지 않기**

킬내기와 빙고는 모두 PUBG 경기 정보를 사용합니다. 두 기능이 각각 처음부터 모든 경기를 다시 수집하면 API 호출이 많아집니다. 그래서 공통 경기 수집기를 두고, 저장된 데이터가 어떤 수준의 통계를 포함하는지 버전으로 구분했습니다. 킬·순위 정도만 있으면 되는 경우와 빙고 미션용 상세 통계까지 필요한 경우를 다르게 처리합니다.

**외부 호출 중 데이터베이스 잠금을 오래 잡지 않기**

PUBG API 응답은 예상보다 오래 걸릴 수 있습니다. 대회 생성·진행 상태 기록과 외부 수집, 집계 결과 반영을 구분해 외부 응답을 기다리는 동안 불필요한 잠금이 이어지지 않도록 했습니다.

**예약 작업과 중복 처리**

킬내기의 마감과 정산, 빙고의 자동 수집과 최종 정산은 서버가 정해진 시각에 처리합니다. 실행할 작업과 상태를 DB에 저장하고, 동일한 작업이 동시에 처리되거나 점수가 두 번 지급되지 않도록 상태 확인과 중복 방지 절차를 마련했습니다.
