# 기술적 문제와 해결 과정

각 사례는 **문제 → 원인 → 대응 → 검증 → 남은 과제** 순서입니다. 확인된 오류와 잠재 위험, 기존 GuildUp에서 얻은 경험을 구별합니다.

## 1. 개발 환경에서의 애플리케이션 실행 오류

**문제:** Java 21·Spring Boot 애플리케이션을 IntelliJ에서 실행하면서 JDK 설정, 실행 구성, 환경변수 등록이 맞지 않아 개발 흐름이 막혔습니다.

**원인/확인:** 프로젝트 SDK와 실행 구성의 JDK를 확인하고, 실행 대상 메인 클래스를 `com.communityplatform.CommunityPlatformApplication`으로 지정해야 했습니다. 환경변수는 애플리케이션 클래스가 아니라 실행 구성에 설정합니다.

**대응:** 프로젝트 SDK와 Maven 설정, Run/Debug Configurations의 메인 클래스·환경변수를 점검했습니다.

**검증:** 개발 대화에서 JDK 문제 해결 후 환경변수 설정 단계로 진행한 것을 확인했습니다. 모든 환경에서 재현 없이 실행됨을 보장하지는 않습니다.

## 2. Discord 고유 ID와 닉네임의 혼동 방지

**문제:** Discord의 표시 이름만으로 사용자를 자동 연결하면 이름 변경과 중복 때문에 다른 계정을 연결할 위험이 있습니다.

**원인:** 닉네임은 사람이 읽기 위한 값이며 고정된 식별자가 아닙니다.

**대응:** 로그인한 서비스 계정의 Discord ID와 동기화된 멤버의 Discord ID를 정확히 비교합니다. 지정 역할과 현재 Discord 서버 소속, 활성 여부를 확인하고, 기존 역할 및 탈퇴/추방 이력을 보존합니다.

**검증:** 2026-11-18 M4 구현 보고에서 자동 테스트 98개 통과. **실제 Discord 동기화와 DB 마이그레이션 검증 전**이므로 현장 동작까지 확정할 수는 없습니다.

## 3. Discord Bot 역할·권한 문제

**문제:** 봇을 서버에 설치해도 기대한 역할이 나타나지 않거나, 봇이 멤버 정보를 읽거나 추방하는 데 필요한 권한이 부족할 수 있습니다.

**원인:** 설치(OAuth2), 서버의 역할 생성, 역할 계층, `Server Members Intent`, 관리자 권한은 별개입니다. 봇을 초대했다고 역할·권한이 자동으로 모두 구성되지는 않습니다.

**대응:** 설치 시 요청 범위·권한과 서버의 봇 역할·역할 순서를 확인하고, 실제로 필요한 Gateway Intent를 기능별로 설정하도록 검토했습니다.

**검증:** 문제 진단 및 설정 가이드 단계. 자동 역할 생성이나 추방 권한 처리의 실제 동작까지 검증된 사례로 서술하지 않습니다.

## 4. 외부 조치의 결과 불명과 중복 실행 — GuildUp 경험

**문제:** Discord 추방 요청이 실행 전에 취소된 경우와, 요청이 전송됐지만 결과를 모르는 경우를 같은 실패로 취급하면 오작동이 발생할 수 있습니다.

**원인:** `gateway.kick()` 호출 시점이 곧 외부 시스템에서 추방을 확정한 시점은 아닙니다.

**기존 프로젝트 대응:** 전송 전 취소는 `SKIPPED`, 전송 후 불명은 `UNKNOWN`으로 구분했습니다. `SKIPPED`에는 짧은 중복 억제를 적용하고, `PENDING`/`UNKNOWN`은 장기 억제를 유지했습니다.

**검증:** 기존 GuildUp 전용 테스트 73개 통과 보고. **이 테스트는 community-platform에 대한 테스트 결과가 아닙니다.**

**새 프로젝트에 반영할 원칙:** 운영자 승인, 작업 상태 기록, 중복 요청 차단, UNKNOWN 상태의 무조건적인 자동 재시도 금지. 설계 채택과 구현 완료를 구분해 추적합니다.

## 5. 새로운 게임 추가 시 기능 결합 위험

**문제:** PUBG 전용 기능을 공통 커뮤니티 기능에 직접 결합하면 다른 게임을 추가할 때 조건문과 스키마 변경이 누적될 수 있습니다.

**원인:** 커뮤니티의 공통 책임과 개별 게임 API의 책임을 분리하지 않으면 확장성이 떨어집니다.

**대응 방향:** 커뮤니티 생성 시 게임을 선택하고 PUBG Kakao/Steam shard를 구별하며, 게임별 수집·활동·UI를 연동 경계로 분리합니다.

**검증:** 설계 및 구현 요청 단계. 실제 새로운 게임 연동으로 확장성을 증명한 단계는 아닙니다.

**작성 원칙:** 재현 로그나 테스트 이름이 없는 곳에 성공률, 속도 개선 수치, 운영 장애 해결 완료 같은 표현을 추가하지 않습니다.
