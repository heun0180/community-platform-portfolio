# 개발 배경

## 클랜을 운영하면서 생긴 불편

배틀그라운드 클랜을 직접 운영하다 보니 게임 외적으로 신경 써야 하는 일이 꽤 많았습니다.

새로운 사람이 들어오면 Discord 닉네임과 PUBG 닉네임을 확인해야 했고, 클랜원들이 얼마나 활동했는지 알아보려면 경기 기록을 찾아봐야 했습니다. 이벤트가 있을 때는 참가자를 정리하고 팀을 나누거나 결과를 기록하는 일도 필요했습니다.

한두 명일 때는 직접 해도 괜찮았습니다. 하지만 이런 작업이 반복되면서, 사람이 직접 확인해야 하는 부분과 프로그램이 대신 처리할 수 있는 부분을 나누고 싶어졌습니다.

## Windows 프로그램에서 웹 서비스로

처음에는 개인적으로 사용하는 간단한 Windows 관리 프로그램을 만들었습니다. 클랜 관리에 필요한 정보를 조금 더 편하게 다루는 것이 목적이었습니다.

이후 Discord의 멤버 정보와 PUBG 경기 데이터를 연결하면 관리할 수 있는 범위가 더 넓어지겠다고 생각해 웹 서비스 **GuildUp**을 개발했습니다. 회원 조회, 활동 확인, 팀 편성, 이벤트 관리처럼 클랜을 운영하면서 필요했던 기능을 하나씩 추가했습니다.

그 과정에서 새로운 고민도 생겼습니다. 하나의 클랜을 기준으로 만든 기능이 다른 커뮤니티에도 그대로 맞지는 않았고, 기능이 늘수록 회원 정보와 Discord 정보, 게임 데이터를 어떻게 구분해야 하는지가 중요해졌습니다.

## community-platform을 새로 만든 이유

GuildUp에서 기능을 구현해본 경험을 바탕으로, 이번에는 처음부터 서비스의 기준을 정리하고 시작하기로 했습니다.

우선 하나의 커뮤니티가 어떤 게임을 사용하는지 명확하게 정하고, 게임마다 서로 다른 기능을 제공할 수 있도록 구성하려고 합니다. PUBG 안에서도 Kakao와 Steam을 구별하고, 앞으로 다른 게임이 추가되더라도 커뮤니티의 공통 기능을 최대한 건드리지 않도록 설계하고 있습니다.

또한 **회원 정보와 실제 클랜원 정보를 분리**했습니다. 웹사이트에 가입한 사용자와 Discord 서버에 있는 클랜원이 반드시 같은 상태는 아니기 때문입니다. 연결할 때도 닉네임을 추측해 매칭하기보다 고유 ID로 확인하도록 했습니다.

마지막으로 활동이 부족하다고 판정된 사람을 바로 추방하는 식의 자동화는 피하려고 합니다. 데이터 수집과 운영자의 판단은 다른 일이라고 생각합니다. 관리에 필요한 근거를 제공하면서도, 영향이 큰 조치는 운영자가 확인할 수 있어야 합니다.

## 만들고 싶은 서비스

운영자가 매번 목록을 뒤져보지 않아도 누가 가입했고, 어떤 게임을 하고 있으며, 최근 활동은 어떤지 확인할 수 있는 서비스입니다. 단순한 관리 화면이 아니라, 클랜을 운영하면서 실제로 겪었던 불편을 줄이는 도구로 발전시키고 싶습니다.
