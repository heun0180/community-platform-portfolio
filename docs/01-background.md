# 개발 배경: 운영자의 반복 작업에서 출발하다

## 출발점

배틀그라운드 클랜을 운영하면서 사람의 손으로 반복하는 일이 많았습니다. Discord에서 구성원을 확인하고, 각 멤버의 게임 닉네임을 대조하고, 최근 경기로 활동 여부를 판단하고, 이벤트를 운영할 때 팀과 결과를 정리했습니다. 단순히 회원 수가 늘어나는 것보다 **정보가 여러 서비스에 나뉘어 있는 것**이 근본적인 문제였습니다.

처음에는 필요한 정보를 간단히 관리하는 **Windows 프로그램**을 만들었습니다. 이후 Discord와 PUBG의 데이터를 연결하여 웹에서 검색·관리·이벤트를 처리할 수 있도록 **GuildUp**을 개발했습니다. `community-platform`은 이 운영 경험을 바탕으로 정책과 데이터 경계를 다시 정의하는 후속 프로젝트입니다.

## 왜 새롭게 설계하는가

- **운영 방식이 커뮤니티마다 다릅니다.** 하나의 클랜에서 잘 동작한 규칙을 모든 커뮤니티에 강제하고 싶지 않았습니다.
- **게임별 연동이 다릅니다.** 같은 PUBG도 Kakao와 Steam을 구분해야 하며, 나중에 다른 게임이 추가될 수 있습니다.
- **확인과 조치를 구분해야 합니다.** 경기 데이터로 활동을 평가하는 것과 실제 회원에게 조치하는 것은 책임이 다릅니다.
- **사용자 식별을 명확히 해야 합니다.** Discord 표시명은 바뀌므로, 계정 연결에는 고유 사용자 ID를 우선합니다.
- **기능 추가보다 지속적인 운영이 중요합니다.** 외부 API 실패·중복 작업·권한 오류 등 실패 조건을 처음부터 설계에 반영합니다.

## 개발 목표

1. 이메일 계정과 Discord 계정을 연결할 수 있는 인증 체계
2. 서로 독립된 커뮤니티와 게임별 설정
3. Discord 역할 기반 클랜원 동기화와 검증 가능한 회원 연결
4. 게임 활동 데이터 조회 및 운영자 의사결정 지원
5. 실행 결과와 실패 사유를 남기는 안전한 운영 기능

**핵심 원칙:** 운영자가 하는 모든 일을 시스템이 대신 결정하기보다, 근거를 빠르게 제공하고 중요한 조치를 통제 가능한 절차로 만드는 데 초점을 맞춥니다.
