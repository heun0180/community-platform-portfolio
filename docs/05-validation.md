# 테스트와 검증 현황

## 왜 검증 단계를 나누는가

자동 테스트 통과는 중요한 근거지만, 실제 Discord 서버에서의 권한, SMTP 발송, 브라우저 OAuth 콜백, PostgreSQL 마이그레이션이 모두 정상이라는 증거는 아닙니다.

| 대상 | 현재 확인된 근거 | 아직 확인해야 할 부분 |
| --- | --- | --- |
| Discord 회원 자동 연결(M4) | 2026-11-18 보고: 백엔드 테스트 98개, 프론트 빌드 통과 | 실제 Discord 동기화·브라우저 화면·개발 DB 마이그레이션 |
| Discord 추방 결과 구분 | 기존 GuildUp 보고: 전용 테스트 73개 통과 | 새 community-platform의 실제 구현·연동 테스트 |
| 게임별 커뮤니티 | PUBG Kakao/Steam 요구 및 게임별 경계 설계 | 새 프로젝트의 shard별 API·데이터 저장 검증 |
| 닉네임 파서 | 추출 규칙·미리보기와 계정 검증 분리 설계 | 실제 이름 변형 및 PUBG 계정 확인 |
| 데이터 격리 | 커뮤니티별 ID/권한 검사 설계 | 커뮤니티 2개 이상의 교차 접근 통합 테스트 |

## 공개 전 체크리스트

- [ ] 로컬 Obsidian 원본과 구현 내역 대조
- [ ] 실제 코드 커밋 및 테스트 실행 결과 대조
- [ ] Discord 권한·봇 설치·동기화 E2E
- [ ] 이메일 가입·검증·비밀번호 재설정 E2E
- [ ] PostgreSQL 마이그레이션 실적 확인
- [ ] PUBG Kakao/Steam API 응답과 데이터 모델 확인
- [ ] 커뮤니티 권한/데이터 격리 회귀 테스트
- [ ] 토큰·이메일·Discord 사용자 ID·DB 연결문자열 제거한 화면 캡처

## 작성 원칙

- 구현하지 않은 기능에는 '예정' 또는 '설계'를 붙입니다.
- 테스트 횟수만 강조하지 않고 **어떤 실패 조건을 검증했는지**를 기록합니다.
- 기존 GuildUp 테스트 결과와 community-platform 결과를 합산하지 않습니다.
- 실제 측정하지 않은 API 호출 감소율, 성능 개선율을 주장하지 않습니다.
