# 테스트와 남은 작업

## 테스트할 때 중요하게 보는 부분

기능 하나가 정상적으로 동작하는 것만큼, **잘못된 입력이나 예상하지 못한 상황에서도 기존 데이터가 망가지지 않는지** 확인하는 것이 중요하다고 생각합니다.

예를 들어 Discord 회원을 연결할 때는 ID가 일치하는 경우만 보지 않습니다. 이미 가입한 회원인지, 운영진 권한을 갖고 있는지, 탈퇴·추방한 이력이 있는지도 함께 확인해야 합니다.

자동 테스트에서는 하나의 Discord 계정이 여러 서비스 계정에 연결되는 것을 막고, 클랜원 자동 연결 때 기존 권한이나 탈퇴 이력을 유지하는지 확인했습니다. 가입 승인 전에는 회원 기능에 접근할 수 없는지, 운영진도 다른 커뮤니티의 회원이나 가입 신청에 접근할 수 없는지 점검했습니다.

랭킹에서는 같은 점수 지급 요청이 동시에 들어와도 한 번만 적립되는지, 출석에서는 서울 시간 자정 전후로 하루 한 번만 지급되는지 확인했습니다.

## 실제 PUBG 데이터로 확인한 것

킬내기의 확인 조회는 실제 PUBG API와 테스트 DB를 연결해 실행했습니다. 대회 마감 전에 시작해 마감 뒤에 끝난 경기도 집계됐습니다. 경기 상세를 어디까지 받아 왔는지는 [킬내기 조회 사례](03-troubleshooting.md#6-짧은-킬내기에도-오래된-경기를-계속-조회했던-문제)에 정리했습니다.

빙고는 별도 스크립트로 PUBG Kakao 경기 텔레메트리를 분석했습니다. 회복 아이템 사용과 팀원 부활처럼 공식 통계와 비교할 수 있는 항목을 대조했고, 낙하산 거리와 화염병 처치처럼 예상과 다르게 기록된 항목은 파서를 수정했습니다. 빙고 서버의 집계 흐름은 테스트 DB에서 확인했습니다.

## 앞으로 확인할 항목

| 기능 | 확인할 내용 |
| --- | --- |
| Discord 실시간 반영과 음성 활동 | 실제 서버에서 닉네임·역할 변경, 음성 채널 이동, 연결 복구 뒤 명부와 세션 기록 확인 |
| 회원 이름 표시 | 운영진이 이름 표시 설정을 바꿨을 때 실제 로그인 화면과 Discord 닉네임 변경 반영 확인 |
| PUBG 클랜 활동 조회 | 운영진이 실제 화면에서 조회를 실행하고 판정 기준과 근거 경기 확인 |
| PUBG 킬내기·빙고 | 실제 로그인 화면에서 참가·집계 확인, 경쟁전 판별과 표본이 부족한 빙고 미션 추가 확인 |
| 랭킹·출석체크 | 개발 DB에 출석 변경을 적용한 뒤 로그인 화면에서 출석과 월간·누적 점수 확인 |
| 공지 | 개발 DB에 공지 변경을 적용한 뒤 로그인 화면에서 작성·고정·새 공지 표시와 임시 저장 복원 확인 |

## 아직 보완할 부분

Discord 실시간 반영·음성 활동·회원 이름 표시 설정·공지·출석체크는 로컬 개발 버전의 자동 테스트와 프론트엔드 빌드 기록을 확인했습니다. 공지와 출석 화면은 모의 데이터 또는 정적 미리보기로 살펴봤습니다. 개발 DB 적용과 실제 로그인 화면에서의 동작 확인이 남아 있습니다.
