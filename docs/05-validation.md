# 테스트와 남은 작업

## 테스트할 때 중요하게 보는 부분

기능 하나가 정상적으로 동작하는 것만큼, **잘못된 입력이나 예상하지 못한 상황에서도 기존 데이터가 망가지지 않는지** 확인하는 것이 중요하다고 생각합니다.

예를 들어 Discord 회원을 연결할 때는 ID가 일치하는 경우만 보지 않습니다. 이미 가입한 회원인지, 운영진 권한을 갖고 있는지, 탈퇴·추방한 이력이 있는지도 함께 확인해야 합니다.

하나의 Discord 계정이 여러 서비스 계정에 연결되지 않는지, 클랜원 자동 연결 때 기존 권한과 탈퇴 이력을 유지하는지 확인했습니다. 가입 승인 전 접근과 다른 커뮤니티의 회원 정보에 접근하는 경우도 점검했습니다.

랭킹에서는 같은 점수 지급 요청이 동시에 들어와도 한 번만 적립되는지, 출석에서는 서울 시간 자정 전후로 하루 한 번만 지급되는지 확인했습니다.

## 실제 PUBG 데이터로 확인한 것

킬내기의 확인 조회는 실제 PUBG API와 테스트 DB를 연결해 실행했습니다. 대회 마감 전에 시작해 마감 뒤에 끝난 경기도 집계됐습니다. 경기 상세를 어디까지 받아 왔는지는 [킬내기 조회 사례](03-troubleshooting.md#6-짧은-킬내기에도-오래된-경기를-계속-조회했던-문제)에 정리했습니다.

빙고는 별도 스크립트로 PUBG Kakao 경기 텔레메트리를 분석했습니다. 회복 아이템 사용과 팀원 부활처럼 공식 통계와 비교할 수 있는 항목을 대조했고, 낙하산 거리와 화염병 처치처럼 예상과 다르게 기록된 항목은 파서를 수정했습니다. 빙고 서버의 집계 흐름은 테스트 DB에서 확인했습니다.

## 데모에서 확인한 것

개발 환경에서 체험 계정으로 로그인해 대시보드와 클랜원 명단, 활동 기록, 킬내기 순위, 빙고판, 랭킹을 열었습니다. 설정을 바꾸려고 했을 때 저장 요청이 거절되는 것도 확인했습니다. 내전의 진행률과 이어 받기, 킬내기의 미리보기와 적용 흐름은 모의 API를 연결한 화면에서 확인했습니다. [데모 버전 구성](06-demo.md)

## 운영에서 확인한 것

2026년 11월 25일 운영 전환 기록에는 GuildUp의 데이터 이전, 새 앱 기동, 사용자 브라우저 확인과 Discord 클랜원 전체 동기화 성공이 남아 있습니다. 이후 운영에서 대시보드 숫자와 필터를 적용한 명단이 일치한다는 사용자 확인을 받았습니다. 최대 100명으로 확장한 버전에서는 내전 편성이 동작했다는 사용자 확인을 받았습니다.

11월 27일에는 비로그인 상태에서 공개 사이트와 로그인 준비 API의 응답을 확인했습니다. 공개 화면을 제공하는 파일에 대시보드의 ‘클랜 활동 없음’, 내전 팀 편성, 킬내기 자동 편성 미리보기·적용 코드가 포함돼 있었습니다.
